# 产品需求文档 (PRD): 七政四余格局系统升级

## 1. 背景与目标

目前的“七政四余”格局系统结构扁平，无法处理以下复杂情况：

1. **多流派分歧**：不同流派（如果老派 vs 琴堂派）对同一个格局的定义不同。
2. **用户自定义**：资深用户希望修改逻辑或添加自己的注解。
3. **跨流派标准**：某些格局是通用的，除非被特定流派覆盖。

**目标**：构建一个灵活的、分层的格局引擎，支持多视角定义、用户覆盖和通用回退机制。

## 2. 用户故事 (User Stories)

* **作为一名学者**，我想在“果老派”、“琴堂派”和“天官派”视图之间切换，以便比较不同流派对同一命盘的解释。
* **作为一名资深用户**，我想“Fork”（克隆）一个标准格局并调整度数容许度（例如，将 5° 改为 3°），让系统按我的规则计算。
* **作为一名初学者**，我想看到标准的格局，而不需要关心复杂的配置（通用回退）。
* **作为一名内容创作者**，我想给特定格局添加注解，分享我的经验。

## 3. 功能需求

### 3.1 核心数据结构

* **隔离性**：将“格局概念”（ID/名称）与“具体定义”（逻辑/来源）分离。
* **通用标记**：定义可以标记为 `is_universal`（通用），默认适用于所有流派。
* **遮蔽机制 (Shadowing)**：特定流派的定义必须覆盖（遮蔽）同一 Pattern ID 的通用定义。

### 3.2 逻辑引擎

* **盲执行**：计算引擎必须只执行提供的 JSON 逻辑，而不需要知道来源（用户 vs 系统）。
* **解析策略 (Resolution Strategy)**：
    1. 用户自定义定义 (最高优先级)
    2. 当前选择的流派定义
    3. 通用定义 (回退兜底)

### 3.3 用户生成内容 (UGC)

* **Forking 机制**：用户可以克隆现有的定义来创建自定义定义。
* **注解 (Annotations)**：用户可以给任何定义附加文本笔记。
* **DSL (领域特定语言)**：一套简化的“功能码”，供用户构建逻辑（例如：`starInGong` 星在宫, `angleBetween` 夹角）。

## 4. 非功能需求

* **性能**：每个命盘的解析逻辑必须在 50ms 内完成。
* **扩展性**：添加新书/新流派应无需修改代码，只需录入 JSON 数据。
* **国际化 (i18n)**：所有 UI 标签和静态内容必须支持中英文。
