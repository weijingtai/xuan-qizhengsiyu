## 当前风险

- **验收风险**：AI agents 已完成编码和多轮测试，但尚缺人类业务验收，不能标记为最终交付。
- **领域风险**：七政四余涉及古籍、历法、岁差、宿度、赤黄道转换和流派差异，自动化测试很难覆盖“术语正确但口径错误”的问题。
- **集成风险**：Flutter module 嵌入宿主 app 后，生命周期、路由、状态恢复、持久化路径、权限和平台差异仍可能暴露问题。
- **数据风险**：当前 asset/golden 测试确认的是版本稳定性，不代表数据来源、抄录、换算和解释已全部正确。
- **协作风险**：仓库存在多个 AI/worktree 产生的并行成果，局部测试通过不等于跨方向组合后无冲突。

## 后续接手建议

1. 先按功能方向建立人工验收清单：四余、三辰通载资产、周天拖拽校准、不等宫覆写分别验收，不要一次性混测。
2. 对每个方向挑选 3 到 5 个真实命例或历史案例，固定输入、期望盘面和人工判读依据，再补业务级 golden。
3. 在宿主 app 中完成至少一次端到端集成测试：创建配置、制盘、拖拽校准、保存、重启恢复、切换流派、回归默认。
4. 对 asset 数据建立人工复核记录：来源页码、转写人、校对人、换算公式、版本号和变更原因。
5. 在人类验收前，不要把上述功能描述为“已交付完成”；更准确的状态是“AI 编码完成，自动化验证通过若干局部门禁，等待人工业务验收和宿主集成验收”。
