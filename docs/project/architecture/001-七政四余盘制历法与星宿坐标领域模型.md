# 七政四余：盘制、历法与星宿坐标领域模型

## 元信息

- 创建日期: 2026-07-04
- 文档类型: 领域模型 / 架构基础知识（Domain Model / Foundational Knowledge）
- 状态: 草稿
- 维护者: wjt
- 适用范围: 星体定位、星宿映射、盘面排布等所有依赖"坐标基准"的子系统（`StarPositionManager`、`ZhouTianModelManager`、`zhou_tian_calculator` 等）
- 关联需求: 梳理"不同朝代历法 × 不同流派 → 不同盘制 → 星宿与星体计算参数 → 古今校验"的完整维度关系

---

## 1. 目标

- 用一套明确的概念框架，描述七政四余排盘中"为什么同一时刻、同一颗星，会算出不同位置"的**根本原因**。
- 把"历法、流派、盘制、星宿定义、星体行度、古今校验"这些相互交织的因素，拆解为**可独立配置的维度**，为后续把它们抽象成数据模型/配置项打基础。
- 作为领域词汇（domain vocabulary）的统一来源，避免代码与文档中概念混用。

## 2. 非目标

- 本文档**不**给出具体的历法算法公式、具体星宿度数表、具体星体速度常数（这些属于数据层与实现层，应在各自的 SPEC / 数据资产中定义）。
- 本文档**不**对"哪个流派/哪套盘制是正确的"做裁定；它只描述维度与差异来源。差异的取舍由具体功能的 SPEC 决定。
- 本文档**不**涉及格局（GeJu）、神煞（ShenSha）、化曜（HuaYao）等上层判断逻辑；它只覆盖它们所依赖的**底层坐标与位置基准**。

---

## 3. 核心命题（一句话模型）

> **「历法 + 流派」两个源头变量相互交织，决定了采用哪一种「盘制」——盘制由「坐标平面（黄道/赤道…）× 零点锚定（恒星制/回归制）」两个正交轴共同刻画；盘制进一步决定了整个周天的「0° 原点」（星体行度的全局起算点）及其随岁差的行为、「二十八星宿」的大小与起点、以及「星体」的行度速度与位置基数；而以上全部参数，最终都要经受「古宿 ↔ 今宿」与「古天文语境 ↔ 今天文语境」的双重校验，其核心机制正是恒星/回归之差带来的岁差累积。**

维度依赖关系（自上而下派生）：

```text
① 历法（朝代/时间）  ─┐                        ┌─→ 周天 0° 原点（全局起算点）
                      ├─→ ③ 盘制（坐标框架）─┼─→ ④ 星宿定义（大小 + 各宿起点）
② 流派（传承/学派）  ─┘                        └─→ ⑤ 星体参数（速度 + 基数）
                                                          │
                                          校验层：古宿↔今宿 / 古语境↔今语境
                                             （横向贯穿 ③④⑤ 全部结果）
```

> ⚠ 区分两个"起点"：**周天 0° 原点**是整个天球坐标系的**全局零点**（一年/星体行度从哪里开始算），全局唯一，是盘制的一项核心输出；**各宿起点**（属 ④）是二十八宿各自的**局部边界**（每一宿从哪里开始）。前者是坐标系原点，后者是原点之上的刻度划分，二者都由盘制确定，但不可混为一谈。

## 4. 维度详解

### 4.1 维度 ①：历法（时间 / 朝代）

- **定义**：不同朝代颁行的历法体系（如各代所用的推步之法）。历法决定了天体位置推算的**时间基准**与**推步规则**。
- **影响**：
  - 同一真实时刻，在不同历法下换算出的"节气 / 干支 / 度数基准"可能不同。
  - 历法是**时间维度**上的变量：它随朝代更迭而变化，是造成"古今差异"的时间侧根源。
- **在模型中的角色**：历法是**输入端的基准来源**，向下影响星体位置基数（④）与星宿起点（③）的取值。

### 4.2 维度 ②：流派（传承 / 学派）

- **定义**：不同的术数传承/学派，对同一套七政四余体系有各自的处理约定。
- **影响**：即便历法相同，不同流派也可能选择**不同的盘制**、不同的星宿起点约定、不同的行度取值。
- **在模型中的角色**：流派是**约定维度**上的变量。它与历法**正交**（orthogonal）——历法解决"时间基准"，流派解决"体系约定"，两者交织共同决定盘制的选取。

> ⚠ 关键点：**① 历法与 ② 流派是两个独立维度，不能合并**。一个流派可能跨多个朝代历法；一部历法也可能被多个流派采用。二者的组合（笛卡尔积）才是真正的"配置起点"。

### 4.3 维度 ③（派生结果）：盘制（坐标框架）

由「历法 × 流派」交织决定，指**用哪一种天球坐标系来安放星体与星宿**。已识别的制式：

| 盘制 | 说明（坐标框架维度） |
|------|----------------------|
| 黄道制 | 以黄道为基准框架 |
| 赤道制 | 以赤道为基准框架 |
| 拟黄道制 | 对黄道框架的一种拟制/近似处理 |
| 天赤道制（365.25） | 以天赤道为基准，采用 365.25 的周天分度体系 |

- **在模型中的角色**：盘制是**第一层派生结果**，是一个"框架选择开关"。它一旦确定，就约束了下面 ④ 星宿定义与 ⑤ 星体参数的具体取值口径。
- **注意**：`365.25` 不是简单的数字，而是**周天分度制**的标志（周天按 365.25 度划分，与 360 度制不同），会直接影响一切"度数"的换算口径。

#### 4.3.1 盘制的核心输出：周天 0° 原点

盘制除了"选框架"，还必须**钉死整个天球的 0° 原点**——即一年 / 星体行度的**全局起算点**（从天空的哪一处开始算 0 度、星体从哪里"起步"运行）。

- **性质**：**全局唯一**的坐标系零点，是所有度数（星体位置、星宿边界）的公共基准。
- **与"各宿起点"（④）的区别**：
  - 周天 0° 原点 = 坐标系**原点**（整片天空只有一个）。
  - 各宿起点 = 原点之上的**刻度边界**（28 个，是对周天的再划分）。
  - 先有 0° 原点，才能谈"某宿起点在几度""某星在几度"。原点一移，所有下游度数整体平移。
- **对下游的影响**：**星体位置基数（⑤）正是相对这个 0° 原点来标定的**——0° 原点变了，位置基数与所有星体度数都要重算。
- **与古今校验的关系**：不同盘制/历法/流派对 0° 原点的选取可能不同；这也是"古今语境位置不一致"（见第 5 章）的重要来源之一——两套语境若零点不同，度数自然对不上。

#### 4.3.2 0° 原点的"锚定方式"：恒星制 vs 回归制

比"选黄道还是赤道"更根本的问题是：**周天 0° 原点到底锚定在什么上、会不会随时间移动**。这就是恒星制与回归制之分。

| 制式 | 0° 原点锚定于 | 一年的定义 | 相对恒星是否漂移 |
|------|--------------|-----------|------------------|
| 回归制（回归/节气制） | **春分点**（黄赤交点，随岁差西移） | 回归年（两次过春分点） | **会漂移**——零点每年相对恒星退行 |
| 恒星制 | **恒星**（某恒定星象基准） | 恒星年（相对恒星回到原位） | **基本不漂移**——零点固定在星空上 |

- **本质区别**：
  - **回归制**的零点跟着**季节 / 节气**走（春分点），因此它对齐的是"寒暑节候"；但由于**岁差**，春分点相对恒星每年缓慢西移（约 71 年 1 度量级），零点因而**逐年偏离恒星**。
  - **恒星制**的零点钉在**恒星**上，对齐的是"星空实位"；节气则会相对这个零点缓慢漂移。
- **与恒星年/回归年的对应**：回归制配**回归年**，恒星制配**恒星年**；两者每年相差的正是**岁差量**。这直接影响 ⑤ 星体的"位置基数"与"速度"口径——用哪种年长做外推，结果不同。

#### 4.3.3 两个轴正交：坐标平面 × 零点锚定

**"黄道/赤道"** 与 **"恒星制/回归制"** 是**两个独立（正交）的轴**，不能混谈：

| | 恒星制（零点锚恒星） | 回归制（零点锚春分点） |
|--|--------------------|----------------------|
| **黄道框架** | 黄道·恒星 | 黄道·回归 |
| **赤道框架** | 赤道·恒星 | 赤道·回归 |

- **第一个轴（平面）**：用**哪个大圆**做基准框架——黄道 / 赤道 / 拟黄道 / 天赤道(365.25)。（见 4.3 表）
- **第二个轴（锚定）**：0° 原点**钉在恒星还是春分点**、会不会随岁差漂移。（本节）
- 一套完整"盘制"= **平面选择 × 锚定方式** 的组合。二者共同决定 0° 原点的位置**及其随时间的行为**。
- ⚠ 实务提醒：七政四余多以**恒星制/宿度**（星空实位）为底，而现代通用天文历（如 `sweph` 默认）多为**回归/黄经**口径；两者相差一个岁差项，**混用必错**（详见第 5 章）。

### 4.4 维度 ④（派生结果）：二十八星宿的定义参数

星宿在不同盘制/历法下，需明确**两个独立的量**：

| 参数 | 含义 | 维度性质 |
|------|------|----------|
| 星宿大小 | 每一宿所**占据天区的弧度**（宽窄） | 每宿一个值，共 28 个值 |
| 星宿位置 | 每一宿在天区中的**起始位置**（从何处起算） | 起点约定 + 各宿累积偏移 |

- **两者相互独立**：知道"起点"不等于知道"宽窄"；两套数据都必须给全，才能确定某度落在哪一宿。
- **随盘制变化**：同一宿在黄道制与赤道制下的大小/起点可能不同（因投影框架不同）。
- **随历法/流派变化**：即便盘制相同，不同历法/流派采用的星宿度数表也可能有差异。

### 4.5 维度 ⑤（派生结果）：星体的运算参数

要算出"某时刻某星在何处"，需要**两类数据**：

| 参数 | 含义 | 维度性质 |
|------|------|----------|
| 星体行度速度 | 各星体各自的运行速率（每单位时间行进的度数） | 每颗星一个（或一组，含迟留伏逆状态） |
| 位置基数 | 计算某一时间点位置时的**起算基准值**（配合速度做外推/内插） | 与历法基准强相关 |

- **计算范式**：`某时刻位置 = 位置基数 + 速度 × 时间差`（概念式，实际含迟留伏逆等非匀速修正）。
- **基数以周天 0° 原点为参照（见 4.3.1）**：位置基数是"在某历法基准时刻，星体相对该盘制 0° 原点的度数"。因此**盘制换了 0° 原点、或历法换了基准时刻，基数都要重新标定**。
- **速度可能依赖流派/盘制**：不同体系对行度的取值可能不同。

## 5. 校验层：古今两套语境的对齐

这一层**横向贯穿** ③④⑤ 的全部结果，是本领域最容易出错、也最需要显式建模的部分。

### 5.1 古宿 ↔ 今宿 校验

- **问题**：古代对二十八宿的定义（起点、宽窄、所指星官）与今日的定义存在差异。
- **要求**：任何一套星宿数据，都要能说明它是"古宿口径"还是"今宿口径"，并提供两者之间的**对照/换算关系**。
- **风险**：若把古宿度数直接套用今宿框架（或反之），会产生系统性偏移。

### 5.2 古天文语境 ↔ 今天文语境 校验

- **问题**：同一颗真实星体、同一个星宿，在**当今天文语境**（现代天文学坐标/星表）下的位置，与在**过去天文语境**（古代观测与推步）下的位置**并不一致**。
- **主因是岁差 + 锚定方式之差**：
  - **岁差**使春分点相对恒星逐年西移。
  - 因此**回归制（锚春分点）**与**恒星制（锚恒星）**的度数差，会随年代**线性累积**（每约 71 年差约 1 度）。年代跨度越大，古今偏差越大。
  - 换言之，5.2 的"古今不一致"与 4.3.2 的"恒星/回归之分"是**同一件事的两个侧面**：锚定方式不同 → 岁差累积 → 古今度数错位。
- **要求**：模型需明确区分——
  - **今语境位置**：以现代天文（如 Swiss Ephemeris / `sweph`）算出的真实天球位置（默认多为**回归/黄经**口径）。
  - **古语境位置**：以古法历法与星宿框架推得的位置（多为**恒星/宿度**口径）。
- **对齐策略**：需要显式决定"以哪一套为准、如何在两套之间映射"，映射的核心就是**扣除/补上对应年代的岁差量**，而不是隐式混用。

> 💡 这解释了为什么工程上会同时存在"现代天文库（sweph）"与"古法排盘规则"两套来源——它们分属两种语境（且常常一个回归、一个恒星），**必须先按岁差对齐、再使用**。

## 7. 对工程/数据建模的启示（非约束，仅提示）

- **配置应以「历法 × 流派」为主键**：一组具体的排盘参数，本质上是"某历法 + 某流派"这一组合下的完整参数包（盘制 + 星宿表 + 星体表）。
- **盘制应拆成两个正交枚举**：平面轴（黄道/赤道/拟黄道/天赤道365.25）与锚定轴（恒星制/回归制）分别建模，不要塞进同一个枚举——否则无法表达"黄道·恒星""赤道·回归"等组合。
- **锚定方式决定是否需要岁差修正**：恒星制不随岁差漂移、回归制随岁差漂移；配置里应能据此判断"给定年代该加/减多少岁差量"。
- **周天 0° 原点应作为盘制的一等配置项**：显式记录每种盘制的全局零点，作为一切度数（星宿边界、星体基数）的公共参照；不可隐含或写死。
- **`sweph` 结果先归一到本系口径再用**：现代历默认多为回归/黄经，古法多为恒星/宿度；接入时应显式做岁差归算，禁止直接把 sweph 黄经当作宿度使用。
- **星宿"大小"与"起点"应拆成两份数据**：不可用单一表混表达。
- **星体"速度"与"基数"应拆开**：基数绑定历法基准时刻，速度绑定流派/盘制约定。
- **古今语境应有显式标记**：任何位置数据都应携带"语境标签"（古 / 今），并有对齐规则，避免隐式混用（尤其是 `sweph` 现代结果与古法结果的混合处）。

以下问题本文档**尚未回答**，留待后续专题 SPEC 或与领域专家确认：

1. 四种盘制（黄道 / 赤道 / 拟黄道 / 天赤道 365.25）之间的**精确换算关系**是什么？

3. 位置基数的**历法基准时刻**如何选定？跨历法如何迁移？
4. 现代天文（sweph）结果与古法结果对齐时，**以谁为准**、误差容忍度如何？
5. 迟留伏逆等非匀速状态，是否需要进入本模型，还是留在计算实现层？
