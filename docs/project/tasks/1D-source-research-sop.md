## 0. 一句话说清楚这件事要干什么

七政四余排盘需要一个"对齐锚点"——即"子宫（或戌宫）0° 究竟落在二十八宿的哪一宿、哪一度"。目前手上有 **5 个互相冲突的候选**，都自称或被归属于《三辰通载》/《开禧历》，但**没有一个已经核实到原始史料出处**。本 SOP 指派你（执行者）去古籍数据库里**找每个候选的原文出处**，让人类最终能基于"哪个候选有真正的史源支撑"来拍板。

**你不是来做天文计算的，也不是来判断哪个对的**——你只做一件事：**把每个候选对应的古籍原文找出来、逐字抄下来、标注出处**。判断和拍板是后面 Claude Code 和人的事。

## 1. 铁律（违反任何一条，这次检索作废）

1. **只检索、不判断**。你不负责决定哪个候选"对"。你负责把找到的原文和出处如实记录，合格/不合格按第 4/5 节的机械标准打标签，标不准的一律标"待补"。
2. **逐字记录原文**。找到的史料描述必须**原文照抄**（连同标点、异体字尽量保留），不要转述、不要改写、不要"翻译成现代话"。转述会丢掉判定所需的关键细节。
3. **出处必须可复核**。每条记录必须给出：书名 + 卷/章/段 + 数据库名 + 可点击 URL（若有）。只给"某古籍记载"这种没法复核的出处 = 不合格。
4. **不凑数、不脑补**。找不到就明确写"史源未找到"。**绝对不允许**为了"每个候选都有交代"而把二手论文的结论、或你自己的推算，包装成"史源"。宁可留空，不可造假。
5. **二手研究 ≠ 史源**。现代论文、百科、博客即便说得头头是道，也只是"线索指引"，用来帮你定位**它引用的那部古籍原文**。最终要记录的是**古籍原文本身**，不是论文的转述。
6. **不网络访问不便时上报**，不要静默跳过。若某个渠道打不开、需要付费墙、检索无结果，如实记录"渠道 X 无法访问/无结果"，换下一个渠道，全部试完仍无 → 标"史源未找到"。

### 每个候选"要找什么"的展开说明

**候选 1 `codeComment_xu6` —— 虚宿6°=子宫0°**
- 找：任何古籍中明确写"虚（宿）六度……子（宫/次/玄枵）……起/初/入"这类把「虚宿 6°」与「子宫起点/黄经 0°」配成一对的原文。
- 首选目标书：《三辰通载》本身（元代星命/历法类）。查证该书是否真有"虚六度起子宫"的表述。
- 次选：任何宋元历法/星命典籍中出现"虚六度"作为子宫（玄枵之次）起点的记载。
- 关键判据：必须是**成对表述**（虚宿某度 ↔ 子宫某位置），孤立出现"虚宿六度"而不与宫位挂钩的，不算。

**候选 2 `kaixiLi_xuwei_zi15` —— 虚危交界=子宫15°**
- 找：《开禧历》中把「虚宿与危宿的分界点」定位到「子宫 15°（玄枵之次中点）」的原文。
- 首选目标书：《宋史·律历志》中收录的**《开禧历》**部分（开禧历行用于南宋，其术文多存于正史律历志）。
- 关键词方向：开禧历 + 步气朔/步日躔/步中星 + 玄枵 + 虚 + 危 + 十五度。
- 关键判据：要能读到"虚危之交 / 虚危分 = 子宫（玄枵）十五度"这种成对定位。

**候选 3 `kaixiLi_kui9_75` —— 奎宿9.75°=戌宫(降娄宫)0°**
- 找：《开禧历》中把「奎宿 9.75°（九度四分之三 / 九度太强 等古度表述）」定位到「戌宫 = 降娄之次 起点」的原文。
- 注意古度写法：古历常用"太/半/少/强/弱"表示分数，9.75° 可能写作"九度太"（太=3/4）或"九度七十五分"等，检索时都要覆盖。
- 首选目标书：同候选 2，《宋史·律历志·开禧历》。
- 关键词方向：开禧历 + 降娄 + 奎 + 九度 + 太/七十五 + 戌。
- 关键判据："奎（宿）九度太 / 九度七十五 = 降娄（戌宫）初/起"这种成对定位。
- **额外价值**：候选 2 与候选 3 同属《开禧历》，若两条都找到原文，可做"同一部历法内部自洽"互校（见第 8 节），这是性价比最高的一步。

**候选 4 `userTableDerived` —— 虚宿1.6275°=子宫0°**
- **这是数学反推值，不是史料**。不要去古籍里找"虚宿 1.6275°"——古人不会写出这么精的小数。
- 你要做的**不是**找它的原文，而是：**核对它所依据的"12 宫对齐分段表"是否有史源出处**。即，用户最初给的那份"子:虚X-危Y…／戌:奎10.2516-娄13-胃7.1863…"的分段表，是否出自某部具体古籍？
- 若能找到该分段表的书面出处，记录之；若找不到（很可能，因为它更像今人整理/软件导出的数值表），如实标注"分段表未见古籍出处，`userTableDerived` 系其数学反推值，非史料"。

**候选 5 `sanChenTongZai_ziwu_unequal` —— 子午30.4380/其余30.4979**
- **这是"宫宽度"数据，不是"对齐锚点"**——它回答"每宫多宽"，不回答"子宫0°落在哪一宿"。（003 §12.2 反复强调这两个是正交变量。）
- 检索目标：《三辰通载》中是否真有"子午两宫各三十度四十三分八十秒（或等价古度写法），其余十宫各三十度四十九分七十九分"这类**十二宫不等宽**的原文记载。
- 关键判据：找到十二宫逐宫宽度的原文即为合格；**但要在报告里显式标注**"此候选只解决宫宽度轴，不含锚点，不能单独用于确定对齐点"。
- 古度换算提示：30.4380° / 30.4979° 是十进制度，古籍多用"度-分-秒（百进）"或"度-太半少"，检索时需按古度写法反查。

## 4. 合格标准（"定案级证词"）——四条全中才算合格

一条记录要被标为 **✅ 合格（定案级）**，必须**同时满足**：

1. **成对表述**：原文明确把"某宿某度"与"某宫某位置（0°/初/起/N 度）"配成一对，例如"虚六度，玄枵初"这种。孤立的"虚宿六度"或孤立的"子宫十五度"都不算成对。
2. **原始引文**：记录的是古籍**原文**（可含影印本），不是今人转述、不是论文改写、不是百科词条。
3. **出处可复核**：书名 + 卷/篇 + 数据库 + URL 齐全，别人能照着点开验证。
4. **非自我存疑**：原文（或最接近原文的精校本）不是作者自己标注"疑""或曰""未详"的存疑句。若原文本身就说"未详"，只能标"待补"。

---

## 5. 不合格标准（一律标"⚠ 待补"，不算定案）

命中以下**任意一条**，该条记录标 **⚠ 待补**，绝不能冒充定案：

1. 只有结论、没有原始引文（例："据载三辰通载以虚六度起子宫"——没给出处原文）。
2. 出处是现代论文/百科/博客的**二手转述**，未回溯到古籍原文。
3. 作者（今人或古人）自己标注"推测""疑""或云""待考"。
4. 找到的是"宫宽度"却被当成"锚点"来交（候选 5 的典型误用）。
5. 数值对得上但**属于另一套口径**（例：把 `userTableDerived` 的反推值当成开禧历原文交上来）。
6. 出处无法复核（说不清哪一卷、给不出可验证链接）。

**待补不是失败**——如实标"待补"是本次检索的合格产出之一。人类拍板时，"某候选史源确实找不到"本身就是有价值的决策依据。

## 6. 必须一并处理的勘误（顺手核实）

003 §15.1 指出一处**史源归属勘误**：代码注释 `zhou_tian_model.dart:61` 把候选 2 归属的历法写成了**《天禧历》**，但正确应为**《开禧历》**（南宋，庆元/开禧年间；"天禧"是北宋年号，另一部历，字形近而非同一部）。

- 检索候选 2 时，请**顺带确认**：史料里把"虚危交界=子宫15°"这条记载系于哪部历法名下，是《开禧历》还是别的？
- 在报告里明确回答："该命题的史料归属 = ___（开禧历/其他），据 ___（出处）"。这条结论将用于修正代码注释与将来资产的 `epochCorrection` 字段。
